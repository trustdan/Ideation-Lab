# Solution-jumping playbook
## When to use
During problem exploration, the group starts proposing specific features or fixes before the
problem statement is validated — listen for "we should just build…" or debate over execution
details with no agreed problem underneath.
## Steps
1. Park it: acknowledge the idea, write it on a visible Parking Lot, don't debate it now. 2.
Reverse-engineer it: ask what user pain point the proposed solution assumes exists. Script:
"That's a concrete idea — let me park it so we don't lose it. What problem does that solve
for the user right now?"
## Output
A parked solutions list plus the group back in problem space; the parking lot itself is worth
a line in `/capture` so ideas aren't lost.
## Facilitation notes
This is a bias toward action, not a bad-faith move — treat it as information about urgency,
not something to shut down. `[[how-might-we]]` is the repair tool if the group needs to
reframe a fixed solution back into an open problem.
